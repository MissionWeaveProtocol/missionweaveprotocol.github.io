# Java referencia de tiempo de ejecución

Esta página cubre la superficie Java completa representada por el
[inventario API exacto](../api/). El comportamiento del protocolo compartido
permanece definido por la
[referencia de tiempo de ejecución ](../../../runtime/architecture-and-bootstrap/)
y las [cláusulas de referencia ](../../../../reference/specification/) locales.
Los tipos de aplicaciones públicas se encuentran bajo
`org.missionweaveprotocol.sdk`; el punto de entrada de conformidad está en
`org.missionweaveprotocol.sdk.cli`.

<SupportStatus status="implemented" /> se aplica a las clases públicas y al
comportamiento en proceso que se enumeran a continuación.

<SupportStatus status="deployment-adapter-required" /> se aplica a la autoridad
Registry actual, al contexto de admisión confiable, al acceso a registros
autenticados y a otros servicios de implementación.

<SupportStatus status="not-implemented" /> significa que el artefacto fijado
exactamente no tiene un tiempo de ejecución correspondiente.

## Artifact y modelo de ejecución

El artefacto Maven es
`org.missionweaveprotocol:missionweaveprotocol-sdk:0.1.0-SNAPSHOT`, compilado
para Java 21 y compilado con Maven 3.9. Declara el nombre del módulo automático
`org.missionweaveprotocol.sdk` y empaqueta el protocolo exacto, la criptografía
y los recursos de admisión dentro del JAR.

La instalación del artefacto no inicia ningún servicio, no abre ningún socket,
no crea ningún almacén duradero y no otorga ninguna autoridad. `IOException`
marcado, las excepciones de verificación y las excepciones de admisión siguen
siendo parte del límite de llamada Java.

## Validación, firma y evidencia Registry

`StrictJson.parse` acepta exactamente un valor UTF-8 JSON.
`SchemaCatalog.packaged` carga los 22 esquemas exactos, mientras que `validate`
verifica un borrador de contrato seleccionado 2020-12.
`CanonicalJson.canonicalize`, `canonicalString`, `sha256Hex` y `canonicalHash`
implementan RFC 8785 y resumen la superficie.

`SigningKey` es la costura de firma propiedad de la aplicación.
`SignedDocumentCodec.sign` y `verify` seleccionan uno de los nueve valores
`SignedDocumentKind` y ejecutan las etapas de análisis, esquema, sobre de firma,
resolución de clave, canonicalización y firma. `KeyResolver.resolve` debe
devolver evidencia `KeyRegistrySnapshot.organizationWide` de una revisión
Organization coherente y aplicable con el historial retenido completo. Una clave
seleccionada, una proyección parcial, un acierto de caché o un indicador de
confianza proporcionado por la persona que llama no son suficientes.

`VerifiedSignedDocument` expone copias defensivas de los bytes recibidos, de
firma y canónicos, además de hashes, tiempo protegido, material de firma y la
clave Registry y Principal resueltas.

## Marcos, paquetes y conformidad

`FrameCodec.decode` y `encode` validan los valores de los fotogramas, pero no
poseen transporte, TLS, autenticación de sesión, persistencia del cursor,
enrutamiento, contrapresión ni transiciones de estado autoritativas.

`ProtocolBundle.verifyPackaged`, `verifyPackagedCryptographyBundle` y
`verifyPackagedAdmissionBundle` validan los pines, recuentos, rutas, longitudes
de bytes y resúmenes exactos del JAR. Las sobrecargas `Path` correspondientes
validan una fuente o una raíz de paquete de versión. Estos métodos no ejecutan
todas las criptografías o evaluaciones de admisión.

`ConformanceRunner.runPackaged` y `ConformanceCli` ejecutan solo los vectores de
esquema estructurales. Al proporcionar `--root PATH` se selecciona un protocolo
explícito o un paquete de versión en lugar de recursos empaquetados.

## Primera admisión

`AdmissionService` expone `prepareFirstAdmission`, `admitFirst` y
`verifyHistoricalAdmission`. Continúe con la
[Java Referencia de admisión](../admission/) para conocer los resultados exactos
del adaptador, el orden de llamadas y el ejemplo del paquete ejecutable.

## Límites de disponibilidad explícitos

<SupportStatus status="deployment-adapter-required" /> **Autoridad de
admisión**: la aplicación proporciona evidencia Registry actual, evidencia
histórica Registry, contexto de aceptación confiable y un registro autenticado
de solo agregar.

<SupportStatus status="not-implemented" /> **Mission orquestación**: no se
exporta ninguna máquina de estado Mission ni fachada de orquestación de alto
nivel.

<SupportStatus status="not-implemented" /> **Programador Worker**: no se exporta
ninguna cola, programador, ejecutor de concesión ni bucle de recuperación
Worker.

<SupportStatus status="not-implemented" /> **Servicio de puerta de enlace
alojada**: el artefacto proporciona `FrameCodec`, no un servicio de puerta de
enlace con propiedad de transporte, TLS, sesión, enrutamiento o contrapresión.

<SupportStatus status="not-implemented" /> **Runtime de persistencia
autoritativa**: no se exporta ningún tiempo de ejecución de persistencia local
respaldado por una base de datos o Agent.

Estas ausencias son parte del contrato de soporte documentado; Las capacidades
de tiempo de ejecución de referencia Python no se deben inferir de los nombres
de protocolos compartidos.
