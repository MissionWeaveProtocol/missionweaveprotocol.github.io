# Python Primera admisión y confianza histórica

Las capas Python `AdmissionService` autenticaron la primera admisión y la
confianza histórica por encima del verificador de seis etapas Signed Document
([MWP-ADM-005](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-005)).
El flujo independiente del idioma de control es la
[página de tiempo de ejecución de confianza histórica y de primera admisión local ](../../../runtime/first-admission-and-historical-trust/),
y los requisitos exactos son las
[cláusulas de confianza histórica y de primera admisión ](../../../../reference/specification/first-admission-and-historical-trust/)
locales].

## Tipos públicos

| Público API                                    | Responsabilidad                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AdmissionCurrentKeyResolver.resolve_current`  | Devuelva evidencia Organization completa de Registry que la implementación afirma que está actualizada para una nueva decisión de primera admisión.                                                                                                                                                                          |
| `TrustedAdmissionContext.issue`                | Emita la identificación del registro confiable, el instante de aceptación confiable y el servicio de aceptación solo después de una ausencia autorizada.                                                                                                                                                                     |
| `AdmissionLog.lookup`                          | Devuelve `AdmissionLookupStatus.FOUND` con bytes autenticados o `AdmissionLookupStatus.AUTHORITATIVE_ABSENCE`. Error de transporte, error de caché, estado indeterminado y error de ausencia no autenticada cerrado en [MWP-ADM-003](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-003). |
| `AdmissionLog.append_or_return_existing`       | Agregue atómicamente bytes candidatos o devuelva el ganador autorizado concurrente.                                                                                                                                                                                                                                          |
| `AuthenticatedAdmissionRecord`                 | Vincule los bytes de registro devueltos a la identidad del servicio de aceptación autenticada por el adaptador para la validación [MWP-ADM-009](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009).                                                                                      |
| `AdmissionService.prepare_first_admission`     | Cree y valide bytes candidatos a partir de un documento ya verificado y un contexto confiable. No anexa ni implica admisión.                                                                                                                                                                                                 |
| `AdmissionService.admit_first`                 | Implemente el flujo de evidencia actual, ausencia autorizada, anexo atómico y registro devuelto en [MWP-ADM-006](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-006).                                                                                                                     |
| `AdmissionService.verify_historical_admission` | Vuelva a ejecutar la verificación con evidencia histórica Registry y solicite un registro encontrado sin emitir contexto ni agregar, como lo requiere [MWP-ADM-008](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-008).                                                                  |

El resultado del adaptador es evidencia escrita. Un valor booleano de confianza
proporcionado por la persona que llama no es un resultado de búsqueda autorizado
y nunca debe seleccionar la ruta exitosa.

## Llamada de primera admisión

:::note[Informative example]

```python
admitted = AdmissionService().admit_first(
    SignedDocumentKind.COMMAND,
    document_bytes,
    current_registry,
    admission_log,
    trusted_context,
)
```

:::

`admit_first` verifica antes de llamar al registro. Cuando la búsqueda devuelve
`AdmissionLookupStatus.AUTHORITATIVE_ABSENCE`, llama a
`prepare_first_admission`, invoca `append_or_return_existing` y luego valida el
registro realmente devuelto. Un ganador simultáneo es aceptable solo cuando sus
bytes, servicio autenticado, enlace de documentos y tiempo confiable se validan
([MWP-ADM-009](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009),
[MWP-ADM-010](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-010)).

## Llamada de repetición histórica

:::note[Informative example]

```python
historical = AdmissionService().verify_historical_admission(
    SignedDocumentKind.COMMAND,
    document_bytes,
    historical_registry,
    admission_log,
)
```

:::

La reproducción histórica utiliza el historial Registry retenido, requiere un
registro de admisión encontrado y nunca llama a `TrustedAdmissionContext.issue`
o `AdmissionLog.append_or_return_existing`. Los ID de registros coincidentes en
el ejemplo demuestran que la reproducción recuperó el primer registro
autorizado; por sí solos no prueban la actualidad de Command, la autorización
del firmante, la aceptación de la máquina de estados ni la verificación portátil
a prueba de registros. La actualización de Command y la autorización del
firmante siguen siendo requisitos separados según
[MWP-ADM-013](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-013)
y
[MWP-ADM-014](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-014).

## Ejemplo ejecutable con fijación exacta

:::note[Informative example]

El ejemplo utiliza solo las API públicas SDK y la dependencia de tiempo de
ejecución `cryptography` declarada. Crea de manera determinista una clave
Ed25519, un Organization completo Registry, un Command firmado y adaptadores en
memoria escritos. La semilla privada fija es material de demostración y nunca
debe usarse fuera del ejemplo.

<pre>
  <code>{ejemplo de admisión}</code>
</pre>

Ejecútelo desde una caja exacta después de instalar todos los extras SDK:

```bash
uv sync --all-extras
uv run python /absolute/path/to/examples/sdk/python/admission.py
```

El resultado esperado contiene el mismo ID First-Admission Record para
`first admission` y `historical replay`. El programa también afirma que los
hashes de firma y los bytes de registro coinciden, y que el registro se agregó
exactamente una vez.

:::

:::note[Implementation note]

Reemplace los adaptadores de ejemplo en una implementación:

- `CurrentRegistryFixture` con un solucionador actual-Registry autenticado;
- `InMemoryAdmissionLog` con un Admission Log atómico autenticado, de solo
  agregar; y
- `FixedTrustedAdmissionContext` con un tiempo de confianza controlado por
  Organization y emisor del servicio de aceptación.

Reemplace `DeterministicSigningKey` con un servicio de firma o adaptador de
claves propiedad de la implementación. Nunca incorpore una semilla de firma
privada en el código de producción.

No colapse esos límites en una sola bandera de disponibilidad o confianza.

:::

El rechazo de admisión poscriptográfico permanece protegido en la etapa
`admission` y el código de conexión `AUTH_INVALID_SIGNATURE`
([MWP-ADM-012](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-012)).
