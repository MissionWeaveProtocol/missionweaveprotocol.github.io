# TypeScript 首次入場與歷史信任

TypeScript `AdmissionService` 在六階段 Signed
Document 驗證器 ([MWP-ADM-005](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-005)) 之上首次准入和信任歷史。與語言無關的流程是本地[首次接納和歷史信任運行時頁面](../../../runtime/first-admission-and-historical-trust/)，確切的要求是本地[首次接納和歷史信任子句](../../../../reference/specification/first-admission-and-historical-trust/)。

## 公共適配器和結果

| 公開 API                                     | 責任                                                                                                                                                                                                                                                 |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AdmissionCurrentKeyResolver.resolveCurrent` | 同步返回完整的 Organization 範圍的 Registry 證據，表明部署斷言對於該決策是最新的。                                                                                                                                                                   |
| `TrustedAdmissionContext.issue`              | 同步或非同步下發可信任記錄ID、受理即時、權威不在後才接受服務。                                                                                                                                                                                       |
| `AdmissionLog.lookup`                        | 非同步返回`{ status: "found", record }`或`{ status: "authoritative-absence" }`。快取未命中、逾時、未經身份驗證的缺席和不確定狀態在 [MWP-ADM-003](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-003) 下關閉失敗。 |
| `AdmissionLog.appendOrReturnExisting`        | 以原子方式追加候選位元組或透過經過驗證的服務身分返回並發權威獲勝者。                                                                                                                                                                                 |
| `AuthenticatedAdmissionRecord`               | 將 `recordBytes` 綁定到適配器驗證的服務，以便 [MWP-ADM-009](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009) 可以驗證傳回的記錄。                                                                              |
| `AdmissionService.prepareFirstAdmission`     | 從 SDK 產生的 `VerifiedSignedDocument` 建立並驗證候選證據。它並不附加或暗示承認。                                                                                                                                                                    |
| `AdmissionService.admitFirst`                | 在 [MWP-ADM-006](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-006) 下執行當前驗證、權威查找、候選創建、原子附加或返回現有以及返回記錄驗證。                                                                     |
| `AdmissionService.verifyHistoricalAdmission` | 根據 [MWP-ADM-008](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-008) 的要求，使用歷史 Registry 證據重新運行六階段驗證，並需要現有記錄而不發布上下文或附加。                                                     |
| `AdmittedSignedDocument`                     | 返回不可變的 `verified` 和 `record` 證據以及防禦性 `recordBytes` 副本。                                                                                                                                                                              |

確切的權威缺席值為
`{ status: "authoritative-absence" }`。呼叫者提供的信任布林值不是准入查找結果，絕不能選擇成功路徑。

## 首次入場電話順序

:::note[Informative example]

```ts
const first = await new AdmissionService().admitFirst(
  SignedDocumentKind.Command,
  documentBytes,
  currentRegistry,
  admissionLog,
  trustedContext,
);
```

:::

`admitFirst`
在查閱日誌之前完成所有六個簽章文件階段。找到的記錄經過驗證並返回，無需發出可信上下文或附加。權威缺席後，服務發布可信任上下文，準備規範候選字節，呼叫
`appendOrReturnExisting`，並驗證實際傳回的記錄。只有當其架構、經過驗證的服務、文件綁定和可信任時間通過
[MWP-ADM-009](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009)
和
[MWP-ADM-010](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-010)] 時，並發獲勝者才是可接受的。

## 歷史回放

:::note[Informative example]

```ts
const historical = await new AdmissionService().verifyHistoricalAdmission(
  SignedDocumentKind.Command,
  documentBytes,
  historicalRegistry,
  admissionLog,
);
```

:::

歷史重播使用保留的 Registry 歷史記錄重新運行驗證，需要
`status: "found"`，並且從不呼叫 `TrustedAdmissionContext.issue` 或
`AdmissionLog.appendOrReturnExisting`。匹配的記錄ID表明恢復了相同的權威記錄；它們不證明 Command 新鮮度、簽署者授權、狀態機接受或便攜式日誌證明驗證。這些在
[MWP-ADM-013](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-013)
和
[MWP-ADM-014](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-014)] 下保持獨立。

## 誤差面

`AdmissionError` 公開 `wireCode: "AUTH_INVALID_SIGNATURE"` 並受保護的
`auditDetail.stage: "admission"`。穩定的受保護原因可區分缺失、衝突、畸形、未經驗證、不可用、不確定和自錨證據，同時保留
[MWP-ADM-012](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-012)
所需的非神諭線結果。

適配器可能會拋出 `AdmissionLogError`
以及受支援的准入原因。其他適配器例外不會自動重新分類。部署必須刻意映射其失敗，並且不得將一般成功、可用性或快取狀態視為經過驗證的證據。

## 可運行的精確固定範例

:::note[Informative example]

這個範例確定性地導出一個 Ed25519
key，建構一個完整的 Registry 快照並簽名 Command，並提供類型化記憶體適配器。固定種子是演示材料，絕不能在範例之外使用。

<pre>
  <code>{typescriptAdmissionExample}</code>
</pre>

從一個精確的 SDK 結帳、類型檢查並運行如下：

```bash
npm ci
cp /absolute/path/to/examples/sdk/typescript/admission.ts examples/website-admission.ts
npm run typecheck:examples
npm run build
node --experimental-strip-types examples/website-admission.ts
```

該套件支援 Node.js 20。直接僅條帶執行此 `.ts` 來源需要 Node.js
22 或更高版本；在 Node.js
20 上，將其與專案一起轉譯 TypeScript 在運行發出的 ESM 之前的工具鏈。預期輸出包含相同的記錄 ID
`first admission` 和
`historical replay`。該程式還斷言匹配的簽章雜湊值和記錄位元組以及精確的一個附加。

:::

:::note[Implementation note]

代替 `CurrentRegistryFixture` 具有經過驗證的當前和歷史 Registry 適配器，
`InMemoryAdmissionLog`
具有經過身份驗證的持久性日誌，其追加或返回現有操作是原子的，並且
`FixedTrustedAdmissionContext` 和 Organization-控制可信任時間和接受服務的發布。

將 `DeterministicSigningKey`
替換為部署擁有的金鑰服務。保留防禦性位元組副本，並且不要將權限邊界折疊為呼叫者提供的信任布林值。

:::
