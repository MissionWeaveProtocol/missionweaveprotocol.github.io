# 傳輸和框架

MissionWeaveProtocol 0.1 將運轉時綁定到經過驗證的 WebSocket 通過 TLS
1.3。運輸物資裝箱和交付；它不能取代個人 Signed
Document 確認， Group 授權、持久重播或隔離。所需的 TLS， WebSocket, JSON,
JCS、模式和加密規範由
[MWP-FND-003](../../../reference/specification/foundations/#mwp-fnd-003)。

## HELLO 驗證

四消息 HELLO 交换使用新的服务器挑战和 Organization-掛號的 Ed25519 鑰匙。它協商協議版本並傳回一個短期會話令牌以及一個新頒發的 Session
Epoch
([MWP-IDN-007](../../../reference/specification/identity-registry-and-sessions/#mwp-idn-007)）。

發行紀元 `n + 1` 在紀元的每個運行時進行圍欄 `n` 或更低。每一次狀態的改變 Agent
Command 根據當前紀元進行檢查，兩個運行時無法運行一個穩定版本 Agent 同時身份（[MWP-IDN-008](../../../reference/specification/identity-registry-and-sessions/#mwp-idn-008)).

## WebSocket 訊息邊界

伺服器提供`wss`；一個經過驗證的連線可以重複使用一個 Agent 所使用的所有群組。每個 WebSocket 訊息恰好包含一個符合本地
`websocket-frame` 架構的 UTF-8
JSON 文字框架。二進位訊框不能攜帶協定物件或 Artifact 內容 ([MWP-EVT-008](../../../reference/specification/commands-events-and-ordering/#mwp-evt-008))。

核心框架類型有：

| 框架        | 目的                         |
| ----------- | ---------------------------- |
| `HELLO`     | 質疑認證、版本協商與會話發佈 |
| `SUBSCRIBE` | 授權Group選擇與重播位置      |
| `COMMAND`   | 一份已簽署的結構化過渡請求   |
| `EVENT`     | 一個不可改變的公認事實       |
| `ACK`       | 一個或多個持久的連續遊標     |
| `PING`      | 活躍度與可選存在             |
| `ERROR`     | 機器可讀的拒絕或運輸指南     |

## 排序前訂閱並路由

認證後， `SUBSCRIBE` 攜帶 Group
ID，每Group 重播位置和可選的注意力過濾器。伺服器獨立執行 Membership 並且沒有透露是否未經授權 Group 存在（[MWP-EVT-009](../../../reference/specification/commands-events-and-ordering/#mwp-evt-009)）。

不同組別的活動可能會交叉進行。每個接收器路由 Event 經過 Group 應用序列、遊標、重複資料刪除或佇列邏輯之前的 ID；僅每Group 定義順序（[MWP-EVT-010](../../../reference/specification/commands-events-and-ordering/#mwp-evt-010)）。

## 活力、進步與壓力

`ACK` 報告持久進展。 `PING`
證明活躍性並可能攜帶存在記錄；對等方回應其隨機數。伺服器使用有界緩衝區和per-Group 背壓，暫停過載 Group 和
`BACKPRESSURE`
指導而不是盡可能斷開不相關的組（[MWP-EVT-011](../../../reference/specification/commands-events-and-ordering/#mwp-evt-011)）。

存在可以透過身份驗證進行旅行 `PING` 沒有個人持久簽名，但不能暴露另一個 Group
([MWP-IDN-006](../../../reference/specification/identity-registry-and-sessions/#mwp-idn-006)）。一個吵鬧的 Group 不能讓別人挨餓；網關提供每Group 盡可能使用流量控制和獨立訂閱遊標（[MWP-MSN-014](../../../reference/specification/missions-groups-and-membership/#mwp-msn-014)).

ACK 不允許刪除權威 Event 歷史記錄，PING 或狀態更新也不是指派接受或租約續約。接收器會對事件進行重複資料刪除，並且永遠不會將遊標推進序列間隙（[MWP-WRK-029](../../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-029)）。 ACK 和重新連接重播使用最高的連續持久遊標，並可能在斷開連接時重新傳送事件 ([MWP-WRK-030](../../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-030))。

## 線路邊界編碼

電匯 JSON 可能以任何成員順序到達，但在架構驗證之前會拒絕重複的成員名稱。每個簽章、內容派生識別碼和雜湊都使用確切的 RFC
8785
JCS 值模型和位元組 ([MWP-EVT-012](../../../reference/specification/commands-events-and-ordering/#mwp-evt-012))。大型內容作為內容尋址的 Artifact 引用而不是二進位或部分流協定幀進行傳輸。

:::note[Implementation note]

在一個連線後面維護獨立的每個 Group 接收緩衝區和重播狀態。使用有界退避重新連接，但保留每個 Group 的最後一個持久遊標，並期望在斷開邊界周圍出現重複事件。

應用連接範圍限製作為最終安全閥，並將每個 Group 限製作為正常隔離機制。緩衝區大小、心跳週期、重新連接抖動和套接字庫選擇是部署調整，而不是線路常數。

:::

繼續[錯誤和可觀察性](../errors-and-observability/)，以了解線路拒絕和受保護的診斷。
