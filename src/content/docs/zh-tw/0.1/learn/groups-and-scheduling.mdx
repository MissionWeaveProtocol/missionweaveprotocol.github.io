# 分組和日程安排

Worker 可以屬於多個 Mission 組，而無需合併其上下文。它為每個 Group 維護一個不同的 Event 收件匣、遊標和工作佇列，並且這些本地投影仍然可以從接受的事件中重建 ([MWP-WRK-008](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-008))。

```text
Group A Event → Group A 佇列 ┐
Group B Event → Group B 佇列 ├→ Worker 排程器 → 隔離執行槽
Group C Event → Group C 佇列 ┘
```

## 誰控制優先級

Coordinator 提供其 Mission 所要求的緊迫性、截止日期和業務影響。 Worker 調度程序對跨 Group 排序擁有最終控制權；一個 Coordinator 無法強制其 Mission 領先於不相關的組([MWP-WRK-009](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-009))。

Scheduler 應用加權公平和抗飢餓。有效排序考慮 Organization 優先級、截止日期、佇列時效、每個 Group 配額、風險閘門和可用資源。
[MWP-WRK-010](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-010)
排除純無界最高優先權優先調度。

## 隔離和時間表披露

每個活動插槽將 Mission 上下文、憑證、檢查點、工具預算和副作用密鑰與每個其他插槽隔離 ([MWP-WRK-011](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-011))。

一個 Worker 可以發布估計的開始和完成視窗、置信度、容量狀態和計算時間，而無需暴露其他內容 Group的身份、內容、分配或確切的全域佇列位置（[MWP-WRK-012](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-012)）。

## 所有權、租賃和安全搶佔

接受後會開始新的 Ownership
Epoch 和啟動截止日期。主動執行使用綁定到 Agent、Session
Epoch、WorkItem、Ownership Epoch、穩定 Lease ID 和到期時刻的 Execution
Lease（[MWP-WRK-013](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-013)）。

優先順序變更會立即對排隊的工作重新排序。活動工作在釋放其插槽之前到達安全、冪等的檢查點：

1. Scheduler請求搶佔；
2. 的 Worker 到達安全檢查站；
3. 的 Worker 記錄檢查點並暫停；
4. 執行槽被釋放；和
5. 的 WorkItem 返回到它的 Group 隊列。

序列為[MWP-WRK-015中規範的合作搶佔模型](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-015)。

## 透過重播恢復

Event 交貨至少一次。一個重新啟動 Worker 恢復每Group 來自快照和有序重播的遊標和佇列，透過以下方式進行重複資料刪除 Event
ID，並且不會在序列間隙上推進持久遊標（[MWP-WRK-029](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-029)）。確認報告最高連續持久位置而不刪除權威 Group 歷史 ([MWP-WRK-030](../../reference/specification/work-scheduling-and-recovery/#mwp-wrk-030)).

MissionWeaveProtocol 定義每個 Group 內的順序，而不定義跨 Group 的全域順序。
