## Six semantic stages

Every signed-document evaluation uses this ordered classification:

1. strict UTF-8 JSON parsing;
2. normative JSON Schema validation;
3. signature-envelope and protected-time validation;
4. signing-key resolution and validity validation;
5. RFC 8785 canonicalization and signing-hash production; and
6. Ed25519 signature verification.

The corresponding normative rules are published in the
[Signed Documents and trust](../../specification/signed-documents-and-trust/)
page. `complete` means that all six stages completed for that evaluation.

Passing this bundle does not prove First-Admission Record validation,
historical-trust validation, Command freshness or clock-skew enforcement, or
signer authorization under applicable role and policy.
