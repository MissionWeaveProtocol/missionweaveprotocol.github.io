# Go ランタイムリファレンス

このページでは、[正確な API inventory](../api/).共有プロトコルの動作は、ローカルの
[ランタイム参照 ](../../../runtime/architecture-and-bootstrap/) および
[参照句 ](../../../../reference/specification/)
によって定義されたままです。以下の名前は、固定されたモジュールがその動作を公開する方法を定義します。

<SupportStatus status="implemented" />
は、以下にリストされているエクスポートされたパッケージ API とインプロセス
コーデックに適用されます。

<SupportStatus status="deployment-adapter-required" /> は、現在の Registry
の権威性、信頼済みアドミッションコンテキスト、認証済みアトミックログ
アクセス、およびデプロイメントによって提供されるその他の外部サービスに適用されます。

<SupportStatus status="not-implemented" />
は、正確に固定されたモジュールに、対応するエクスポートされたランタイムがないことを意味します。

## インポートと実行モデル

単一のパッケージを
`missionweaveprotocol "github.com/missionweaveprotocol/go-sdk"`
としてインポートします。このモジュールには Go
1.24 が必要です。パブリック名は Go エクスポート ルールに従います。アンエクスポートされたヘルパーと実装アダプターはアプリケーション コントラクトではありません。

このモジュールは、JSON、暗号、埋め込み、および I/O の標準ライブラリに加えて、宣言されたスキーマと RFC
8785 の依存関係を使用します。パッケージのインストールだけでは、プロセスの開始や権限の作成は行われません。

## 検証と暗号

`DecodeJSON`
はサポートされている厳密な JSON データ モデルを強制し、`SchemaCatalog`
は正確に埋め込まれたドラフト 2020-12 スキーマ セットを検証します。
`CanonicalizeJSON` および `MarshalCanonicalJSON` は RFC
8785 バイトを生成します。これらは別個のゲートです。スキーマの成功は、正規の証拠や署名された証拠を意味しません。

`SignedDocumentCodec.Sign`
は、明示的なドキュメントの種類を選択し、保護された時刻を検証し、署名なし射影を正規化し、`SigningKey`
を呼び出し、Ed25519 エンコードをチェックし、エンベロープを添付して、結果を検証します。
`Verify`
は生のバイトを消費し、解析、スキーマ、署名エンベロープ、鍵解決、正規化、署名の各ステージを順番に実行します。返された
`VerifiedSignedDocument`
は、防御バイトのコピー、署名と完全なハッシュ、保護された時間、署名の証拠、および解決されたキーを公開します。

`KeyResolver`
は、Organization 全体の Registry の完全な証拠を返す必要があります。選択されたキー、マップ エントリ、または呼び出し元が提供した信頼フラグが不十分です。

## フレーム、バンドル、および適合性

フレーム関数は値を解析およびエンコードしますが、ソケットを開いたり、セッションを認証したり、カーソルを永続化したり、作業をスケジュールしたり、権威ある遷移を適用したりすることはありません。これらは、展開またはより高いレベルの実行時の責任です。

`VerifyProtocolBundle`、`VerifyCryptographyBundle`、および
`VerifyAdmissionBundle`
は、各埋め込みアーティファクト セットをその記録された ID にバインドします。
`RunEmbeddedConformance`
は、埋め込まれた構造ベクトルを実行します。 SDK コミット、プロトコル PIN、スキーマ セット、暗号バンドル、アドミッション バンドル、またはデプロイメント アダプターが変更されたときに、これらを再度実行します。それらに合格することは、パッケージ表面が行使されたことのみを証明します。

## 初回アドミッション

`NewAdmissionService` は、正確なスキーマのサービスを構築します。
`PrepareFirstAdmission`、`AdmitFirst`、および `VerifyHistoricalAdmission`
は同期 Go 呼び出しであり、アダプター エラーまたは検証エラーを返す可能性があります。
`AdmissionCurrentKeyResolver`、`TrustedAdmissionContext`、および `AdmissionLog`
はデプロイメント インターフェイスのままです。正確な結果、アトミック性の要件、および歴史的なパスについては、[Go アドミッション リファレンス ](../admission/)
に進んでください。

## 明示的な可用性境界

<SupportStatus status="not-implemented" /> **Mission オーケストレーション** -
高レベルの Mission ステートマシンまたはオーケストレーション
ファサードはエクスポートされません。

<SupportStatus status="not-implemented" /> **Worker スケジューラ** - Worker
キュー、スケジューラ、リース ランナー、またはリカバリ
ループはエクスポートされません。

<SupportStatus status="not-implemented" /> **ホストされたゲートウェイ サービス**

このモジュールは、トランスポート、セッション、TLS、ルーティング、またはバックプレッシャーの所有権を備えたゲートウェイサービスではなく、フレーム コーデックを提供します。

<SupportStatus status="not-implemented" /> **権威ある永続性ランタイム** -
データベースベースまたは Agent
ローカルの永続性ランタイムはエクスポートされません。

これらの未実装項目は、サポートされるランタイム契約の一部です。アプリケーションは、共有プロトコル名から Python リファレンスランタイムの機能を推測してはなりません。
