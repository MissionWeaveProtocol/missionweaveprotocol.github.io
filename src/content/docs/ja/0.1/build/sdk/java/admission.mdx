# Java 最初の入場と歴史的信頼

Java `AdmissionService` は、6 段階の Signed
Document 検証者 ([MWP-ADM-005](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-005))] の上に、初回入場と歴史的信頼を重ねます。言語に依存しないフローはローカルの
[初回入場および歴史的信頼ランタイム ページ ](../../../runtime/first-admission-and-historical-trust/)] であり、正確な要件はローカル
[入場条項 ](../../../../reference/specification/first-admission-and-historical-trust/)] です。

## パブリックアダプターと結果

| パブリック API                                     | 責任                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AdmissionCurrentKeyResolver.resolveCurrent`       | デプロイメントがこの決定に対して最新であると主張する完全な Organization 全体の Registry 証拠を返します。                                                                                                                                                                                 |
| `TrustedAdmissionContext.issue`                    | レコード ID を発行し、信頼できる即時受け入れを行い、正式な不在の後にのみサービスを受け入れます。                                                                                                                                                                                         |
| `AdmissionLog.lookup`                              | `AdmissionLookup.Found` または `AdmissionLookup.AuthoritativeAbsence` を返します。キャッシュミス、タイムアウト、または認証されていない不在により、[MWP-ADM-003](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-003)] に基づいてクローズが失敗します。 |
| `AdmissionLog.appendOrReturnExisting`              | 候補バイトをアトミックに追加するか、認証されたサービス ID を通じて同時に権威のある勝者を返します。                                                                                                                                                                                       |
| `AuthenticatedAdmissionRecord`                     | [MWP-ADM-009](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009)] のアダプターによって認証されたサービスに、返されたレコード バイトをバインドします。                                                                                                |
| `AdmissionService.prepareFirstAdmission`           | SDK によって生成された `VerifiedSignedDocument` から候補証拠を作成および検証します。追加したり、承認を暗示したりするものではありません。                                                                                                                                                 |
| `AdmissionService.admitFirst`                      | [MWP-ADM-006](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-006)] に基づいて、現在の証拠を確認し、検索し、不在後の準備をし、既存の追加または返却を行い、返されたレコードを検証します。                                                               |
| `AdmissionService.verifyHistoricalAdmission`       | 過去の Registry 証拠を使用して検証を再実行し、コンテキストを発行したり [MWP-ADM-008](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-008)] に基づいて追加したりせずに既存のレコードを要求します。                                                      |
| `PreparedFirstAdmission`、`AdmittedSignedDocument` | 不変の検証と記録の証拠を保存し、防御的なレコードバイトのコピーを返します。                                                                                                                                                                                                               |

呼び出し元が提供する信頼ブール値はアドミッション検索結果ではないため、成功パスを選択してはなりません。

## 初回受付の電話順番

:::note[Informative example]

```java
AdmittedSignedDocument first =
    new AdmissionService()
        .admitFirst(
            SignedDocumentKind.COMMAND,
            document,
            currentRegistry,
            admissionLog,
            trustedContext);
```

:::

`admitFirst`
は、ログにアクセスする前に 6 つの検証段階をすべて完了します。見つかったレコードは検証され、信頼できるコンテキストの発行や追加を行わずに返されます。正式な不在の後、サービスはコンテキストを発行し、正規の候補バイトを準備し、`appendOrReturnExisting`
を呼び出し、実際に返されたレコードを検証します。同時勝者は、スキーマ、認証、ドキュメント バインディング、および信頼できる時間が
[MWP-ADM-009](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009)
および
[MWP-ADM-010](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-010)] を満たす場合にのみ成功します。

## 過去のリプレイとエラー

`verifyHistoricalAdmission` は `KeyResolver`
を使用し、6 つのステージすべてを再実行します。`AdmissionLookup.Found`
を必要とし、`TrustedAdmissionContext.issue` または
`AdmissionLog.appendOrReturnExisting`
を呼び出すことはありません。レコード ID が一致すると、同じ権限のあるレコードが復元されますが、[MWP-ADM-013](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-013)
および
[MWP-ADM-014](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-014)] に基づく Command の鮮度、署名者の承認、ステートマシンの受け入れ、またはポータブル ログプルーフ検証は証明されません。

6 段階の障害は `SignedDocumentVerificationException`
のままです。アドミッション ステージの障害は、ワイヤ コード
`AUTH_INVALID_SIGNATURE` の `AdmissionException`、ステージ `admission`、および
[MWP-ADM-012](../../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-012)] で要求されている型付き
`AdmissionReason` です。デプロイメント・アダプターは `AdmissionAdapterException`
をスローします。一般的な成功や可用性は、認証された証拠ではありません。

## 実行可能な完全に固定された例

:::note[Informative example]

この例では、正確な JAR にパッケージ化されたリソースから署名付き Command および Registry を読み取り、型指定されたメモリ内権限アダプターを提供します。リポジトリ ファイルは読み取りません。これは、初回受付と履歴再生に対して同一のレコード ID、署名ハッシュ、レコード バイトを 1 回の追加でアサートします。

<pre>
  <code>{javaAdmissionExample}</code>
</pre>

それを正確なチェックアウトにコピーして実行します。

```bash
cp /absolute/path/to/examples/sdk/java/AdmissionExample.java \
  examples/src/main/java/org/missionweaveprotocol/examples/AdmissionExample.java
./mvnw -B -ntp verify
./mvnw -q -Dexec.mainClass=org.missionweaveprotocol.examples.AdmissionExample \
  -Dexec.classpathScope=test exec:java
```

予期される出力には、`first admission` と `historical replay`
の同じレコード ID が含まれています。

:::

:::note[Implementation note]

`CurrentRegistry`
を認証された現在および過去の Registry アダプタに置き換え、`InMemoryAdmissionLog`
を既存の追加または返却操作がアトミックである認証された永続ログに置き換え、`FixedTrustedContext`
を次のアダプタに置き換えます。 Organization によって制御される信頼できる時間とサービスの発行を受け付ける。防御的なコピーを保持し、これらの権限境界を呼び出し側が提供する 1 つの信頼ブール値に決して分解しないでください。

:::
