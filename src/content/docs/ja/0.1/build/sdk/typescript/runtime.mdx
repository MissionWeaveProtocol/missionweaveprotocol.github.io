# TypeScript ランタイムリファレンス

このページでは、[正確な API インベントリ](../api/)
で表される完全な TypeScript サーフェスについて説明します。共有プロトコルの動作は、ローカルの
[ランタイム参照 ](../../../runtime/architecture-and-bootstrap/) および
[参照句 ](../../../../reference/specification/)
によって定義されたままです。以下の名前は、固定されたパッケージがその動作を公開する方法を定義します。

<SupportStatus status="implemented" /> は、以下にリストされているパッケージ
ルート API およびインプロセス コーデックに適用されます。

<SupportStatus status="deployment-adapter-required" /> は、現在の Registry
の権威性、信頼済みアドミッションコンテキスト、認証済みアトミックログ
アクセス、およびデプロイメントによって提供されるその他の外部サービスに適用されます。

<SupportStatus status="not-implemented" />
は、正確に固定されたパッケージに対応するパブリック
ランタイムがないことを意味します。

## インポートと実行モデル

`@missionweaveprotocol/sdk`
からパブリック名をインポートします。このパッケージは ESM および CommonJS エントリ ポイントを公開し、Node.js
20 以降が必要です。 `@missionweaveprotocol/sdk/admission`
などのサポートされているサブパスは公開されません。以下のソース モジュール名は、単一パッケージ ルート API の出自グループです。

SDK は、スキーマ、適合性、暗号化、およびアドミッション バンドルにノード暗号化とパッケージ化されたファイル システム アセットを使用します。ピン留めされたパッケージは、ブラウザーまたは Deno ランタイムのサポートを要求しません。

## 完全なソース マップ

| ---------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| パッケージ ID と JSON タイプ | `src/index.ts`、`src/json-types.ts`             | パッケージのメタデータ、プロトコル定数、およびパブリック コーデックで受け入れられる JSON ドメイン タイプ。                                                                                       |
| 厳密な JSON と時間の値       | `src/strict-json.ts`、`src/rfc3339.ts`          | パッケージルートの厳密な解析エクスポートとパブリック `Rfc3339Instant` タイプ。内部 RFC 3339 パーサーと検証専用の strict-JSON ヘルパーは、パッケージ ルート エクスポートではありません。          |
| スキーマカタログ             | `src/schema-catalog.ts`                         | 2020-12 ドラフト パッケージ化されたプロトコル セットでのスキーマの検出、検証、および構造化検証の失敗。                                                                                           |
| 正規 JSON                    | `src/canonical-json.ts`                         | RFC 8785 署名およびダイジェスト入力のための正規化とバイト生成。                                                                                                                                  |

| フレーム                     | `src/frame-codec.ts`                            | サポートされている WebSocket フレーム オブジェクトの厳密な解析およびエンコード操作。これはコーデックであり、ホストされたゲートウェイ サービスではありません。                                    |
| 適合性とバンドル             | `src/conformance.ts`、`src/package-root.ts`     | パッケージ化されたルートの検出、構造マニフェストの実行、および `missionweaveprotocol-conformance` コマンド。暗号化および入場アセットはパッケージ化されていますが、公開検証ランナーはありません。 |
| 初回アドミッション           | `src/admission.ts`                              | 6 段階の検証が成功した後に階層化された、型付きの初回アドミッションと履歴信頼のフロー。                                                                                                           |

## 検証と暗号化

`parseStrictJson` および `parseStrictJsonObject`
は、無効な UTF-8、BOM、重複したオブジェクト メンバー、サポートされていない数値入力、および文書化された JSON パイプライン外のその他の構文を拒否します。
`SchemaCatalog` は、パッケージ化されたスキーマ セットを正確に検証します。
`canonicalJsonBytes` は RFC
8785 バイトを作成します。スキーマ検証が成功しただけでは、正規化や署名検証に代わるものではありません。

`SignedDocumentCodec.sign`
は、明示的なプロファイルを選択し、保護された時刻を検証し、署名されていない投影を正規化し、`SigningKey`
を通じて厳密な 64 バイトの Ed25519 署名を取得し、エンベロープを添付して、最終文書を検証します。
`verify`
は、生の UTF-8 バイトを消費し、解析、スキーマ、署名エンベロープ、鍵解決、正規化、署名の各ステージをこの順序で実行します。返された
`VerifiedSignedDocument`
は、不変の証拠、防御バイトのコピー、署名と完全なハッシュの両方、保護された時間、および解決されたキーを公開します。

鍵の解決には、Organization 全体の Registry の完全な証拠が必要です。選択したキー、キャッシュ エントリ、または呼び出し元が提供した信頼フラグは、完全な Registry スナップショットではありません。

## フレーム、バンドル、および適合性

`FrameCodec`
は、サポートされているフレーム値を解析およびエンコードしますが、ソケットのオープン、セッションの認証、カーソルの永続化、作業のスケジュール設定、権威ある遷移の適用は行いません。デプロイメントでは、これらのより高いレベルの実行時の責任を提供する必要があります。

`packageRoot` は、`PROTOCOL_PIN.json`
を見つけて、パッケージ化されたアーティファクト ツリーを見つけます。そのファイルを見つけても、その内容や成果物のダイジェストは検証されません。
`runConformance`
は、パッケージ化されたスキーマ カタログを通じて構造適合マニフェストとベクターのみを実行します。
`missionweaveprotocol-conformance` コマンドは、同じ構造ランナーを呼び出します。

ピン留めされたパッケージには、正確なリリース来歴を示す暗号化およびアドミッション アセットが含まれていますが、暗号化またはアドミッション バンドル ダイジェストを検証したり、それらの評価マニフェストを実行したりするパブリック API は公開されません。アプリケーションは、`packageRoot`
または成功した構造適合レポートを、これら 2 つのバンドルが検証された証拠として扱ってはなりません。

## 初回アドミッション

`AdmissionService` は、同期の Signed
Document 検証の上に、非同期の候補準備、初回アドミッション、および履歴リプレイを公開します。現在の Registry 解決は同期です。信頼済みコンテキストの発行は同期または非同期です。Admission
Log の検索と追加は非同期です。アダプターの正確な結果と呼び出し順序については、[TypeScript アドミッションリファレンス](../admission/)を参照してください。

## 明示的な可用性境界

<SupportStatus status="not-implemented" /> **Mission オーケストレーション** -
高レベルの Mission ステートマシンまたはオーケストレーション
ファサードはエクスポートされません。

<SupportStatus status="not-implemented" /> **Worker スケジューラ** - Worker
キュー、スケジューラ、リース ランナー、またはリカバリ
ループはエクスポートされません。

<SupportStatus status="not-implemented" /> **ホスト型ゲートウェイ サービス** -
このパッケージは `FrameCodec`
を提供しますが、トランスポート、セッション、TLS、ルーティング、またはバックプレッシャー所有権を持つホスト型ゲートウェイ
サービスではありません。

<SupportStatus status="not-implemented" /> **権威ある永続性ランタイム** —
データベースベースまたは Agent
ローカルの永続性ランタイムはエクスポートされません。

これらの未実装項目は、サポートされるランタイム契約の一部です。アプリケーションは、共有プロトコル名から Python リファレンスランタイムの機能を推測してはなりません。
