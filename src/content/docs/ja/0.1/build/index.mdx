# MissionWeaveProtocol 0.1 ランタイムをビルドする

:::caution[Draft Standard 0.1]

このバージョン管理された Build パスは、規範的な Web サイト公開物の一部です。ローカルの Reference 条項を再定義せず、実装順に整理します。要約とリンク先の条項が食い違う場合は、リンク先の条項が要件を決定します。

:::

ローカル仕様で使用される BCP 14 要件言語は
[MWP-FND-001](../reference/specification/foundations/#mwp-fnd-001).共有パスは、すべての言語実装が保持する必要があるセマンティクスを記述します。 SDK 固有のページには、インストール コマンド、言語タイプ、および公開 API 構文が追加される場合がありますが、これらのルールを弱めたり置き換えたりしてはなりません。

:::note[Implementation note]

## 推奨される実装順序

1. 正確なリリース、信頼境界、バリデーター、ストア、およびランタイムをブートストラップするアイデンティティ。
2. プロトコル JSON、識別子、タイムスタンプ、ハッシュ、エンベロープ タイプを保持します。ホスト言語の正規化なし。
3. 厳密な解析、スキーマ検証、正規化、署名を実装します。Registry に基づく鍵解決と 6 段階の検証パイプライン。
4. 暗号検証の上に重ねる初回アドミッションと履歴信頼。
5. 権威ある状態を再構築可能なプロジェクションから分離し、実装するリプレイ、冪等性、フェンシング、および副作用の回復。
6. 標準の WebSocket フレーム上でグループを認証し、多重化します。
7. 保護された診断機能と有用な機能を維持しながら、安定したワイヤ エラーを公開します。操作信号。
8. 正確なリリース成果物を検証し、証明された適合サブセットを報告し、ワイヤーセマンティクスをサイレントに変更することなくアップグレードできます。

この命令は実装ガイダンスです。リンクされた参照条項は、要件とその許容範囲を定義します。

:::

## コードの前にリリースする

固定されていないリポジトリ ブランチや SDK README ではなく、ローカルの
[標準リリースのidentity](../reference/normative-release/)
から開始します。リリース ページには、プロトコル アーティファクト、6 つすべての SDK コミット、プロファイル、ダイジェスト、ロケール、およびこのドキュメントで使用される正確な構築サイト ID がバインドされています。
