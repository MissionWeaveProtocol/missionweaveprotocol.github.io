# 首次准入与历史信任

准入是经过六阶段密码验证后的一个单独的语义层。它不会更改签名字节、签名哈希、密钥解析或签名结果 ([MWP-ADM-005](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-005))。其先决条件是完整的六阶段结果 ([MWP-SDV-015](../../../reference/specification/signed-documents-and-trust/#mwp-sdv-015)) 以及与准入无关的签名哈希 ([MWP-SDV-017](../../../reference/specification/signed-documents-and-trust/#mwp-sdv-017)) 和正确的当前或历史 Registry 证据合约（[MWP-SDV-010](../../../reference/specification/signed-documents-and-trust/#mwp-sdv-010)）。

## 需要的接口

准入层取决于这些不同的证据和权限边界：

:::note[Implementation note]

用类型化接口表示每个边界：

- 新的首次接纳决定的当前 Registry 证据；
- 权威历史Registry证据供回放；
- 经过身份验证的 Admission Log 查找；
- 一个原子追加或返回现有操作；和
- Organization-仅在权威缺席后使用受信任的接受上下文。

:::

Admission Log 逻辑密钥是
`(organizationId, signingHash)`。它必须对接受服务进行身份验证，区分发现和权威缺席，保留仅附加完整性，并因不可用、不确定、未经身份验证、完整性失败、冲突或提交失败结果而失败关闭（[MWP-ADM-003](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-003)）。调用者提供的信任布尔值不是这些结果之一。

逻辑键最多存在一条权威记录。重试时发现的相同有效记录是幂等成功，而冲突的文档类型、密钥 ID 或 Principal 会被拒绝而不是被替换 ([MWP-ADM-004](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-004))。

## 首次接纳算法

```text
six-stage cryptographic verification
→ authoritative Admission Log lookup
→ found record validation OR authoritative absence
→ trusted context and candidate preparation
→ atomic append-or-return-existing
→ returned record validation
→ admitted result
```

只有权威缺席才允许可信的上下文获取和候选人准备。追加可能会返回本地候选人或并发获胜者，并且返回的记录始终在成功之前经过验证（[MWP-ADM-006](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-006)）。

First-Admission
Record 是一个单独的无符号九字段对象。它不会对自身进行身份验证，并且不能包含
`signature`
([MWP-ADM-001](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-001))。保留`trustedAcceptedAt`的词法拼写；将其作为 RFC
3339 即时进行比较，而不需要受保护文档时间使用的大写 `Z`
拼写 ([MWP-ADM-002](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-002))。

候选准备不会附加 Event、执行转换或暗示成功。并发获胜者可能会返回不同的记录 ID 或可信时间，但只有经过验证的返回字节才能成功 ([MWP-ADM-007](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-007))。

## 返回记录验证

记录验证：

1.严格解析恰好一个UTF-8 JSON值；2.应用规范的First-Admission Record
Schema；3. 比较 `organizationId`、`documentKind`、`signingHash`、`keyId`，以及
`principal`
与六阶段结果完全一致；4. 将`acceptedBy`与认证的服务身份进行准确比较Admission
Log适配器；和5. 独立检查 `trustedAcceptedAt` 与所选密钥的保留情况半开有效区间。

确切的绑定规则为[MWP-ADM-009](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-009)，可信时间间隔规则为[MWP-ADM-010](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-010)。仅验证候选字节是不够的。已签名的 Event 不能充当其自己的 First-Admission
Record；稍后的 Event 只能发布或引用单独的记录 ([MWP-ADM-011](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-011))。

## 历史回放

```text
six-stage cryptographic verification with authoritative historical Registry evidence
→ required found record
→ record validation
→ no trusted context or append
```

重播无法创建丢失的准入、发出新的可信上下文或将旧文档视为新准入的文档 ([MWP-ADM-008](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-008))。

## 入学后的界限

承认的结果仍然无法建立 Command 新鲜度或签名者授权。新提出的 Command 具有单独的新鲜度和时钟偏差检查（[MWP-ADM-013](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-013)），并且相关机构在受保护和可信的接受时间分别验证签名者的角色和策略（[MWP-ADM-014](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-014)）。

每次加密后准入失败都会保留受保护的阶段 `admission` 并在线上映射到
`AUTH_INVALID_SIGNATURE`
([MWP-ADM-012](../../../reference/specification/first-admission-and-historical-trust/#mwp-adm-012))。

:::note[Implementation note]

将当前密钥解析、历史密钥解析、Admission
Log 访问和可信上下文获取保留为不同类型的适配器，即使一项服务实现了其中多个适配器。这可以防止缓存未命中、传输错误或调用者布尔值被错误地表示为权威缺席。

适配器 API 应返回经过身份验证的服务身份以及找到或附加的字节，以便记录验证不会意外信任从记录本身获取的
`acceptedBy` 字段。

:::

使用本地 [准入一致性捆绑包](../../../reference/conformance/admission/)
测试首次准入和历史重放，包括失败的适配器结果。
